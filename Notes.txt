In the dictionary for each effect, the duration of the effect is given in real time minutes,
the time the effect actually takes in the real world.
The duration is then adjusted for model railroad 'scale' and converted to milliseconds.


Write about the effect buffer


SINGLES effects have one waypoint. The duration is defined as 0, since 'infinately long' seems rediculous.
The random value is a float between 0 and 1. 0 is not random, 1 is maximum randomness.



Animated Effects:

There were two ways to code an animated effect, either hold the await constant and have different increments for each color, or have all colors have the same increment and have a different await for each color (5 asyncio loops). In testing the first one was better, the color transitions could be controlled to eliminate noticeable stepping as the effect progressed.

controller.MRLI:
run_lighting_effect()
When a new effect is chosen, it elbows the current one out of the way and starts running beginning at the selected waypoint. The first try-block sets the waypoints. The second try-block increments the color changes, it tries to run states.animated_increment_waypoint().

When entities.WP_DUR is counted down to zero, the first try-block will run the states.aniamated_set_next_waypoint() method. This method will populate entities.WP_DUR, entities.WP_NAME, entities.NEXT_WP (an index) and entities.CLIP_G. It will also populate the five entities.STEP<color> values. In the future, LED banks might be toggled here as well, but for now they don't change during an animated effect.
An animated effect will loop back to the first waypoint after it completes the last waypoint.

Within the dictionary for each animated effect are two parameters; CLOCK_CYCLE and CLOCK_OFFSET.
CLOCK_CYCLE is used to control noticeable stepping as the color values change, especially when the scene is dark.
CLOCK_OFFSET is used to compensate for uAsyncio overhead. This allows the waypoint to run for an expected amount of time.

Static Effects:

Static effects have only one waypoint, therefore the end is the same as the beginning, so waypoint duration becomes irrelevant. All the static effects are grouped together in a dictionary called SINGLES.

Sound effects:

controller.MRLI:
play_ambient_effects()
Since it never stops running silence is accomplished by sending a silent clip to the player. Sound effects are combined together in groups. A sound effect group is assigned to every waypoint, animated and static. The code randomly selects a sound effect from the group and adds a pad of random length to the end of the sound effect. The sound effect length and pad are used as the asyncio wait. Sound effects are pushed to the player, messages are sent back from the player but I don't use them.

Visual effects:

Sound effects drive visual effects, and are triggered by a field in the sound effects tuple.

Lightning:

The lightning visual effect uses only the cool LEDs. A bunch of tuples are described in entities.LIGHTNING. The values are pwm brightness and millisecond duration.
The code selects a subset of this.
First it creates a new list of random length between 5 and 10. Then it populates the new list by randomly picking tuples from entities.LIGHTNING. The random list of random elements is then run. What's nice is that after the effect is run the code politely returns to the waypoint progression.

Operations:

PAUSED:
Onle animated effects can be paused. Set next waypoint and increment waypoint have no method for PAUSED, so that even though the asyncio-while loop keeps going, no action is taken. Same for play_ambient_effects(). Since there is no paused_play_sound() method, the currently playing clip will finish and no new one will be played.

STANDBY:
When the machine is put in standby, animated effects are paused. The LED banks are turned off so the machine looks like it's turned off. Sound effects are treated the same as PAUSED.

Waypoint Duration:
Waypoint duration is not a time per se, it is the number of cycles the waypoint awaits before moving on to the next waypoint. The actual amount of time (milliseconds) the waypoint takes is WP_DUR * CLOCK_CYCLE.

Uasyncio:
uAsyncio has overhead. It is predictable which is nice so I compensate for that by speeding up the effect with entities.CLOCK_OFFSET.

At this point the animated effects do not synchronize with any external time source, and the WIFI feature of the Pico is not utilized.
